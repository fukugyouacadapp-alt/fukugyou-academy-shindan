あなたはWebサービスの開発者です。以下の仕様で「複業診断」サイトを作ってください。
仕様に書いていない細かい点は、このサービスの目的（1章）に照らして妥当なほうを選び、選んだ理由を最後にまとめて報告してください。

## 1. 何を作るか

- **サイト名**：強みから見つける「複業診断」（2026-10-25 に「複業ニッチ診断」から変えた）
- **表記**：画面の文は「複業」と書き、「副業」は使わない（2026-10-26 にそろえた）。結果の部品の決まりは `docs/02-result-rules.md` の5章
- **ひとことで**：選択式の質問に答えると、その人の強みを「#ハッシュタグ」で言葉にし、その強みが活きる**ニッチな複業（ライバルの少ない、対象を絞った仕事）**を3つ提案する無料診断サイト
- **運営**：複業アカデミー（Color WiTh株式会社）
- **目的**：複業アカデミーの入口。「自分にも複業の可能性がある」と実感してもらい、無料相談・LINE登録につなげる
  - 2026-10-31 に、複業アカデミー様の要件定義（最新版・2026-10-29。https://shindan.optima-sail.com/youken ）に合わせて、診断の途中経過（チェックポイント）・強みの六角形・結果の一部を伏せて面談へつなぐ形に変えた。この仕様書と要件定義が食い違うときは、要件定義が正本
  - 結果で仕事を1つに絞らず3つ出すのは、わざとそうしている。「3つのうちどれから始めるか」を講師との面談で相談してもらい、診断から面談へつなぐため（2026-10-28 に書き足した）。結果を1つに絞る・「これが正解」と言い切る形には変えない
- **使う人**
  - 30〜40代の会社員。複業に興味はあるが「自分に何ができるかわからない」人
  - 「Webライター」「動画編集」のような、よく聞く複業しか思いつかない人
  - X や LINE のリンクから、スマホで来る人が多い

**診断を終えた人に感じてほしいこと**

1. 「自分の強みって、こう言えばいいのか」― 強みが言葉になる
2. 「こんな仕事があるのか。しかも自分に向いている」― 思いつかなかった選択肢に出会う
3. 「これなら今週から動ける」― 最初の一歩がわかる

結果が「誰にでも当てはまる占い」に見えたら失敗です。**その人が選んだ回答の組み合わせを引用して、その人だけの結果に見せる**ことを最優先にしてください。

## 2. 診断の土台になる考え方（複業アカデミーの教材より）

設問・結果の組み立て・結果画面のすべてで、この考え方を一貫して使ってください。

### 2-1. 複業 ＝ 複数の本業を積み重ねて、可能性を拡げる働き方

本業を捨てて別の副業を始めるのではなく、本業で培ったものを起点に外へ広げていく。

### 2-2. 強みの3層（本業 → 顕在型 → 潜在型）

見本：`docs/reference/skill-layers.png`（教材スライド）

| 層 | 意味 | 例 |
|---|---|---|
| 本業 | いまの仕事でそのまま使っているスキル | #採用支援 #提案営業 #研修講師 #事業開発 |
| 顕在型 | 本業スキルを、別の会社・別の立場で活かす仕事。本人も「できる」と自覚している | #業務改善フロー構築 #プロジェクトマネジメント #キャリアコーチング #COO |
| 潜在型 | 本業の延長で培った経験や、仕事の外で積み上げてきたこと（子育て・発信・地域活動・趣味など）を活かす仕事。本人の自覚は薄い | #子育て講師 #コミュニティ運営 #X運用 #バックオフィス全般 |

内側（本業）から外側（潜在型）へ向かう矢印で「可能性が拡がる」ことを表します。

### 2-3. 強みの3要素（マインド／テクニック／ナレッジ）

> 考え方として残しています。結果画面には出していません（2026-10-24 に欄を外しました）。

- **マインド**（姿勢・価値観）例：傾聴、寄り添い／Giveの精神／挑戦意欲が高い
- **テクニック**（再現できるやり方）例：潜在ニーズの言語化が得意／相手の懐に入るのが得意
- **ナレッジ**（知識・経験・資格）例：中小企業診断士の経営知識／大企業での業務経験
- 3つが重なるところ ＝ **その人ならではの強み**。「〇〇が可能 ⇒ 根拠となる実績」の形で書く
  例：感情と論理を組み合わせた経営コンサルが可能 ⇒ 3年間で50社の実績

### 2-4. 得意な市場・領域（対極の2軸）

市場を対極の2軸で切り、自分が得意な範囲を示す。軸の例：
toB／toC、ゼロから立ち上げる／整えて伸ばす、大企業／中小企業、都市／地方、デジタル推進／アナログ文化、前に出る／裏方、スペシャリスト／ジェネラリスト、既存事業／新規事業

### 2-5. 強みは「#ハッシュタグ」で表す

自己紹介や案件検索にそのまま使える言葉にする（#人柄がいい ✗ → #採用面接代行 ○）。

## 3. 画面と流れ

```
トップ → 診断 STEP1〜5（9画面。STEP2・3・4 の後に途中経過を1画面ずつ） → 読み解き中（約3.6秒） → 結果（一部を伏せる） → 面談の予約
```

診断は**5つのステップ・全10問**（設問1〜8 ＋ 最後の深掘り1問）、所要時間は**約3分**です。

| 画面 | URL | 中身 |
|---|---|---|
| トップ | `/` | 見出し・所要時間・はじめるボタンだけ |
| 診断 | `/shindan` | 設問。1画面に1〜3問、上部に進み具合のバーと「何画面目か」 |
| 結果 | `/result` | 診断結果（5章）。`/result?sample=1` を開くと、結果の見本（10章のAさんの回答で組み立てたもの）を表示する |
| プライバシー | `/privacy` | 回答の扱い（保存しないこと） |

### トップ

- 説明のまとまりは置かず、見出しとボタンだけの短いページにする（中央にそろえる）
- 上から順に：小見出し「複業アカデミーの無料診断」／見出し「あなたの強みに合う複業がわかる」／「選ぶだけ約3分・無料・登録不要」／「無料診断スタート」ボタン（上のふちに「かんたん約3分」の札。濃いふち・下の影・右の三角で立体に見せる。サイトの見た目の決まりの例外）
- 「結果の見本を見る」リンクは 2026-10-25 に、トップと結果ページの「まだ診断していません」画面の両方から外した（見本のページ `/result?sample=1` 自体は、動作確認用に残す。URLを直接開けば出る）
- 見出しは、幅が狭いときだけ「あなたの強みに合う」「複業がわかる」の2行に折り返す（言葉の途中で切らない）
- 回答の取り扱いは、ページ下（フッター）の「回答の取り扱い」から `/privacy` へ（要件定義 R6「運営者と結果の扱いが分かる」は、このフッターで受ける。見出しの下に運営者と回答の扱いの1行を足したが、2026-10-31 に不要として外した）。フッターと `/privacy` の「運営」の欄には、運営会社のプライバシーポリシー（https://color-with.com/privacy-policy/ 、別のタブで開く）へのリンクも置く

| 2 | 1 | 2 | |
| 3 | 2 | 3 | |
| 4 | 2 | 4 | |
| 5 | 3 | 5 | |
| 6 | 3 | 6 | |
| 7 | 4 | 7-1・7-2 | |

**途中経過（チェックポイント）**：STEP2・3・4 を答え終えて「次へ」を押すと、次の STEP の前に途中経過を1画面はさむ（要件定義 R11。2026-10-31 に足した）。途中で終わったと思わせず、「完成した形を見たい」気持ちで最後まで答えてもらうため。
- 中身：小見出し「途中経過」／「診断はまだ続きます。あと◯問」（◯はこの後に残っている質問の数。スライダーは1つずつ数える。いまの設問だと STEP2 の後が8問、STEP3 の後が6問、STEP4 の後が1問）／描きかけの六角形（答え終えた力だけ色が付き、残りの軸は点線、名前は「?」）／「完成度 2/6」と進み具合の棒（STEP3 の後は 4/6、STEP4 の後は 5/6）／「いまのところ、いちばん高いのは「〇〇」。」と、その力の一言／「残りの◯つの力は、この先の質問で見えてきます。」（5/6 のときは「最後の1つの力は、結果画面でそろいます。」）
- ボタンは「続きを答える」の1つだけ。ここで離れる人を減らすため、画面の下に固定し、墨の塗り・白い太字で、ほかのボタンよりひと回り大きくする（高さ56px）。結果画面の予約ボタン（オレンジの塗り）とは色を変える。ボタンのすぐ上に「選ぶだけ、あと約◯分で結果がわかります」と残りの手間を添える（2026-10-31。最初は白地に墨のふちだったが、目立たないので変えた）。予約ボタンや結果の文面は置かない
- 「次へ」のたびと同じく履歴を1つ足すので、ブラウザの「戻る」で直前の設問に、「進む」で途中経過に戻れる
- 六角形の6つの力の決め方は `docs/02-result-rules.md` の7章

### 診断画面のルール

- **すべて選択式。文字を入力する欄は1つも作らない**（「その他（記入）」も置かない）
  - 選択肢にぴったり当てはまらない人（いくつかの仕事にまたがる人・まだ名前のない仕事をしている人）には、言葉で手当てする。1の補足（4章）と、結果の「次の一歩」の一言（5章の8）。記入欄を足す案は 2026-10-28 に見送った（AIを使わない作りなので、書いた言葉を結果に活かせない。回答の取り扱いのページの「入力する欄はありません」という約束も崩れる）
- 1画面に1〜3問（並びは上の表）。戻るボタンあり。スマホやブラウザの「戻る」でも1つ前の画面に戻る（「次へ」のたびに履歴を1つ足す。アドレスは /shindan のまま）
- 途中でページを閉じても、回答はブラウザ内に残る（sessionStorage）。次に開くと「前回の続きから再開しています。」と出し、「はじめからやり直す」も選べるようにする
- 前の答えを変えて、聞かなくなった設問の答えは消す（1の仕事のタイプを選び直したときの1-2「具体的には？」の答えと、1-2を選び直したときの9の深掘りの答え）
- 選択肢は押しやすいボタン型（チップ）。複数選ぶ質問は「2つまで選べます（1/2）」のように上限と選んだ数を表示し、上限に達したら残りを押せなくする。「特にない」は他と一緒に選べないようにし、線で区切って最後に置く
- 上部に、進み具合のバー・何画面目か（例「4 / 9」）・「あと約◯分」を表示する（最後の画面では「あと少し」）
- 「次へ」は、その画面の質問にすべて答えるまで押せない。押せないあいだは、ボタンの上に「すべての質問に答えると「次へ」が押せます」と理由を表示する。最後の画面（STEP5）のボタンは「結果を見る」
- 選んでも自動では次へ進まない。どの画面も「次へ」を押して進む（選び直してから進めるように）

## 4. 設問（すべて選択式）

設問は8つ（1〜8）と、最後の深掘り（9）の1問で、全10問です。答えやすさを優先して、選択肢は1問あたり5つ前後に絞っています。選択肢を大まかにした分は、1-2「具体的には？」と、最後の深掘り（STEP5）で具体的にします。

選択肢は `src/data/questions.ts` にまとめ、1つずつIDを付けて管理してください。IDは「設問ID.番号」の形です（例：`q3.2`）。1-2「具体的には？」は仕事のタイプごとに別の設問として持ち、IDは `q1_2_<タイプの番号>.番号` にします（例：「人事・採用」は `q1_2_3.1`）。9の深掘りも仕事の内容ごとに別の設問として持ち、IDは `q9_<タイプの番号>_<内容の番号>.番号` にします（例：「人事・採用」の深掘りの「面接・選考」は `q9_3_1.1`）。並び順を変えるとIDがずれるので、公開後に選択肢を足すときは、ふつうの選択肢の最後に足してください（診断の途中だった人の回答がずれないように。ただし「特にない」が付いている設問では、いつも最後に置く「特にない」のIDだけは1つずれます）。「特にない」系は、いつも最後に置きます。下の文言は画面にも、結果の「向いている理由」などの引用にもそのまま使います。結果の部品（`src/data/catalog/`）もこのIDで回答を見ているので、選択肢を変えたら `npm run check:results` で点検します。表の設問は、画面に出る順に並べています。

各STEPの見出しと、見出しの下に添える一文：

| STEP | 見出し | 見出しの下の一文 |
|---|---|---|
| 1 | あなたの仕事 | まずは、いまのお仕事について教えてください。 |
| 2 | あなたの強み | まわりから見たあなたを思い浮かべて選んでください。 |
| 3 | 相手と経験 | 仕事に関係ないことでも大丈夫です。意外な強みのタネになります。 |
| 4 | これからの働き方 | 直感で選んでください。 |
| 5 | 最後に、もう少しだけ | お仕事の中身を、もう少しだけ教えてください。提案する仕事がより具体的になります。 |

画面の上部には「STEP 2 / 5　あなたの強み」のように、STEPの番号と見出しを出します。

- **「得意な市場」の2軸はプログラムが決める**。3つのうち、0から最も離れている2つを選ぶ（-2・+2 が先、次に -1・+1）。離れ具合が同じなら 8-1 → 8-2 → 8-3 の順で先にあるものを選ぶ。1つ目を横の軸、2つ目を縦の軸にする（使い方は6章）

## 5. 結果画面

   - 伏せた仕事は、ぼかしと鍵で「中身がある」ことを見せる。ぼかしの下に置くのは、どの人にも同じ見本の文（「あなたの経験が活きる、ねらい目の仕事の名前」「向いている理由：…」「最初の一歩：…」「1年の道のり：…」）と、その人の順位・顕在型／潜在型だけ。本物の仕事の名前や理由は画面に入れない（ぼかしは見た目だけなので、ページの中身を覗けば読めてしまうため）。鍵の枠には「3つの仕事の中身は、無料面談で」「仕事の名前・向いている理由・最初の一歩・1年の道のりを、講師が面談でお伝えします。」と、下の面談の予約へ飛ぶ「面談について見る」

## 6. 結果の組み立て（AIは使わない）

- 結果は、**あらかじめ用意した文面の部品**（`src/data/catalog/`。仕事のタイプごとに1ファイル）を、回答に合わせて選び・組み立ててつくる（`src/lib/diagnose.ts`）。選び方と、部品の書き方の決まりは `docs/02-result-rules.md`
- **ブラウザの中だけで組み立てる**。回答をサーバーにも外部のAIにも送らない。APIキーも、回数制限も、サーバー側の仕組みも要らない
- 同じ回答からは、いつも同じ結果になる。組み立てた結果は sessionStorage に保存し、回答を変えたら消す
- 回答は選択肢のIDで持ち、組み立ての前に確かめる（選択肢にないID・上限を超える数・「特にない」と他の同時選択があれば、途中の回答として続きへ案内する）。文言は設問データから引くので、勝手な文章が結果に混じらない
- **「得意な市場」の2軸はプログラムが決める**（決め方は4章 STEP4 の 8。2026-10-31 から画面には出していない）
- **強みの六角形（6つの力）と、合う複業の方向もプログラムが決める**（`src/lib/radar.ts`。決め方は `docs/02-result-rules.md` の7章）
- 部品を足す・直したときは `npm run check:results` で点検する。部品そのもの（数・文字数・書き方・書いてはいけない言葉・回答IDの書き間違い）と、でたらめに作った2万通りの回答で組み立てた結果（3件・顕在型2件・理由の引用がその人の選んだ回答の言葉か・使える時間の制約など）を確かめる。AIを呼ばないので料金はかからない
- 結果はすぐできるが、答え終えてから結果へ切り替わる間として、約3.6秒の「読み解き中」を見せる（2026-10-26 に2.4秒から延ばした）。待っている目印は、複業アカデミーのロゴを左右にゆらしながら軽く弾ませる動き（2026-10-26 に、回る輪から変えた。動きを減らす設定の人には止めて見せる）。ロゴのまわりの輪に、上から時計回りにオレンジの線が伸び、結果が出る少し前に一周して満ちる（あとどれくらいかが目でわかるように。この輪は動きを減らす設定の人にも進めて見せる）。「強みを読み解いています」の下に作業の段階（回答を整理しています → 強みをハッシュタグにしています → 6つの力を六角形にしています → ニッチな複業を3つに絞っています）を順に進め、選んだ回答の言葉を「」付きで1つずつ流す

## 7. デザイン

- 配色は運営会社サイト（color-with.com）に合わせる：白地・墨の文字・オレンジ（押すもの・印）・青（リンク・潜在型）。教材スライドのオレンジ→黄→青緑の帯は、ページ上端の細い帯と「可能性を拡げる」矢印にだけ使う
- ハッシュタグは教材と同じく「角丸の枠＋色文字」のチップ。本業・顕在型はオレンジ系、潜在型は青系など、層で色を分ける
- 選択肢のボタンも同じ「角丸のチップ」で統一し、選ぶと色が塗られる
- 結果画面のイラストは unDraw（商用利用可・クレジット不要・改変可）の絵を、サイトのオレンジ・青に塗り替えて `public/illustrations/` に置く。アイコンは Tabler Icons（MIT License）の線の絵を `src/components/result/Icon.tsx` に写して使う。利用条件は `public/third-party-licenses.txt`。unDraw は自動での取り込みを認めていないので、足すときはサイトの「Download SVG」ボタンから取り込む
- 吹き出しの見出しは淡いオレンジの塗りにして、濃いオレンジで塗った「押すもの」（ボタン）と見分けられるようにする
- **スマホ優先**（幅375pxで完璧に見えること）。指で押しやすい大きさ（高さ44px以上）にする。PCでも崩れないこと
- 文字は読みやすい日本語ゴシック（Noto Sans JP など）、本文16px以上
- 避けるもの：紫のグラデーション、絵文字の多用、すりガラス風の装飾、意味のないアニメーション（よくある"AIっぽい"見た目）
- 結果ページの主役は「自分のことが書いてある」という感覚。装飾より読みやすさを優先する
- 色・文字・角の丸みなどの細かい決まりは、`src/app/globals.css` の冒頭と `src/app/tokens.css` にまとめる（運営会社サイト color-with.com から読み取った値）。色は tokens.css の名前で引き、画面側に色の値（#hex）を直接書かない

## 8. 技術と環境

- Next.js（App Router）＋ TypeScript ＋ Tailwind CSS。公開先は Vercel
- 外部のAIは使わない。結果はブラウザの中で、用意した部品から組み立てる（6章）
- 第1段階では、データベースとログインは使わない。回答はブラウザの sessionStorage にだけ置き、サーバーには保存しない。プライバシーページにもそう書く
- 計測：Vercel Analytics で「診断開始」「診断完了」「申し込みボタンのクリック」を数える。回答の中身は送らない
- **このPC固有の注意（必読）**
  - 開発サーバーは `npm run dev` で起動し、中身は `next dev --webpack` に固定する。Turbopack は使わない。このPCの別プロジェクトで、Turbopack と Tailwind の組み合わせから PostCSS の子プロセスが増殖し（240個・12.7GB）、PCがメモリ不足で固まったことがある（2026-08-20）。このプロジェクトでは、起動のルールを `CLAUDE.md` に書き、`npm run dev` の直前に残ったプロセスを掃除する `scripts/kill-postcss-orphans.js` を自動で走らせて防ぐ
  - Next.js 16 は従来と仕様が違う（例：middleware.ts → proxy.ts）。コードを書く前に `node_modules/next/dist/docs/` の該当ガイドを読む
  - 最初に `CLAUDE.md`（起動手順と注意点）を作る

## 10. 完了の条件
